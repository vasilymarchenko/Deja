# Second Brain

**Одним рядком.** Особиста пам'ять для всього, що ти свідомо зберіг: сторінки, репозиторії, пости, відео — і власні ідеї. Зберігаєш одним кліком — знаходиш через півроку одним запитанням.

## Проблема

Закладки, «прочитати пізніше», збережені повідомлення та зірки на GitHub — це кладовища. Туди легко покласти й майже неможливо дістати: ти пам'ятаєш *сенс* («графік про інфляцію в Болгарії», «репо з цікавим підходом до тестів»), а система зберігає лише URL і заголовок. Універсальні чати цього не вирішують — у них немає твоїх даних і твого контексту.

Те саме з ідеями: «о, хочу зробити X, але не зараз» губиться в чатах із самим собою, нотатках і голові. Через півроку ти пам'ятаєш, що *щось таке думав*, але не де і не що саме.

## Для кого

Зараз — один розробник, який багато читає та дивиться кількома мовами й працює з AI-асистентами. Архітектурно — багатокористувацький сервіс з ізольованими даними; масштаб — тисячі записів на користувача.

## Що робить

1. **Захоплення.** Розширення Chrome з двома режимами:
   - *Джерело* — одна кнопка на поточній сторінці з полем «навіщо зберігаю» (LLM пропонує формулювання, ти підтверджуєш або правиш).
   - *Ідея* — текстове поле для власної думки на кілька речень; поточну сторінку можна прикріпити як тригер. LLM пропонує короткий заголовок і якорі.
2. **Збереження та індексація.** Джерело зберігається цілком: текст сторінки, README і метадані репо, розшифровка відео, текст поста. Ідея зберігається як написана. Поверх будується індекс: фрагменти з прив'язкою до місця в оригіналі (абзац, таймкод), мультимовні ембедінги, 3–7 якорів виду «сутність + аспект» і підтверджений тобою рядок «навіщо». Повторне збереження того самого джерела не дублює запис, а доповнює його; для ідей те саме працює за схожістю сенсу — система пропонує доповнити близьку ідею, а не створити нову.
3. **Пошук.** Запитання природною мовою → гібридний пошук за фрагментами та якорями → джерело й точка всередині нього: стаття, прокручена до абзацу, відео на потрібній хвилині, або ідея разом із матеріалами, що її викликали.

## Ключова відмінність

Пошук не за текстом, а за *твоєю причиною збереження*. Рядок «навіщо» та якорі ловлять те, чого в тексті немає словами — сам графік, сам прийом у коді. Для GitHub-репо це головний сигнал: README мало говорить про те, чому репо тебе зацікавило.

## Ідеї

Ідея — це перевернутий запис: у звичайного запису головне — джерело, а «навіщо» лежить поверх; в ідеї головне — твій текст, а джерела опціональні й лежать під ним. Все інше спільне: фрагменти, якорі, пошук.

- Ідея може бути без джерел, з посиланням на одне чи кілька — прикріплених у момент збереження або доданих пізніше. Кожне таке посилання — звичайний запис, з яким ідея пов'язана.
- Ідея — write-once: збереглась і забулась, система поверне її за сенсом. Доповнення — лише через повторне збереження; редактора, папок і зв'язків руками немає.
- У пошуку ідеї змішані з джерелами: запитання «що я думав робити з локальними ембедінгами» знаходить і ідею, і статті, що її викликали. Окремо — фільтр за типом, щоб переглянути всі ідеї списком.

## Принципи

- **API-first.** Розширення — перший клієнт HTTP API з ключем. Усі майбутні інтерфейси (веб, бот, MCP для AI-асистентів) — такі ж клієнти того самого API.
- **Мультитенантність у схемі з першого дня.** `user_id` на всіх даних, API-ключі на користувача. Реєстрація, RLS і білінг — лише коли з'явиться друга людина.
- **Життєвий цикл запису у схемі з першого дня.** Кожний запис має поля терміну дії та нагадування (порожні у v1). Логіка поверх них — пізніше, але переїзд схеми без них був би болючим.

## Чим не є

Не нотатник: власні думки зберігаються так само, як джерела — один раз, без редагування, папок і структурування. Не RSS-рідер, не архіватор усього трафіку, не таск-менеджер, не командний інструмент, не локальна модель на ноутбуці.

## Межі v1

- **Джерела:** веб-сторінки, GitHub-репо, Telegram-пости (за посиланням), YouTube, власні ідеї.
- **Інтерфейс:** лише розширення Chrome — захоплення (джерело / ідея) та пошук.
- **Пошук:** гібридний (BM25 + вектор за фрагментами + вектор за якорями), без багатокрокового ретрівера.
- **Хостинг:** Hetzner CX23, Docker Compose (Caddy, FastAPI, Postgres + pgvector), черга завдань у таблиці Postgres, бекапи `pg_dump`.
- **Зберігання:** близько 150 КБ на статтю; десять тисяч записів — 1,5 ГБ. Ідеї — кілобайти, не впливають.

## Дорожня карта

- **v2** — веб-інтерфейс зі списком збереженого (окремо — списком ідей) та пошуком.
- **v3** — Telegram-бот (мобільний ввід, голос — основний вхід для ідей) і MCP-сервер для AI-асистентів.
- **Напрямок: проактивність.** Система не лише відповідає, а й сама повертає збережене: нагадування про ідею через заданий час або за подією, термін дії записів (TTL) із м'яким «забуванням» — архівуванням замість видалення, дайджест «ти зберіг це півроку тому — ще актуально?». Поля для цього закладені у схему з v1; логіка й інтерфейс — після того, як накопичиться корпус і стане зрозуміло, що саме варто повертати.
- **Далі** — реєстрація користувачів, якщо з'явиться попит.

## Критерій успіху

Через півроку використання запитання «де я це бачив…» (у тому ж числі «що я думав про…») у семи випадках з десяти закривається першою відповіддю.
